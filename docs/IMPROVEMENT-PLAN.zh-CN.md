## 目标与范围

以现有图谱、题库、静态诊断应用为基础，先交付一套可审核的初中统计与概率样板，再扩展到初中数学全科、小学衔接及高中。英语继续保留，但不纳入第一阶段内容质量承诺。

成功标准是：能力范围清楚、课标要求可追溯、题目能检验对应能力、先修边有理由、诊断结论与实际证据相匹配。节点数和题目数只作规模指标，不作为完整性或教学有效性的证明。

## P0：先建立审核依据和第一份样板

### P0-1 课标版本与覆盖审计

交付建议：`reviews/math-junior/standards-audit.json`、`reviews/math-junior/README.md`、`data/source-registry.json`。

1. 分别登记 2022 与 2025 修订版的官方来源、文件指纹、获取日期、印刷页与 PDF 页换算。对未取得或未核对的材料明确标记，不继承标题中的“已对齐”结论。
2. 逐条核对初中 157 条内容要求，记录要求动词、普通或选学、考试边界、原条款编号、来源版本及页码。
3. 同条混合普通与选学要求时，增加子要求 ID，不改写原编号；沿用已有 ID 的意义，避免为插入新条目而重排 ID。
4. 将“是否有引用”和“是否充分覆盖”分开。覆盖状态用明确、部分、缺失、待核，附判断理由、节点和评估证据。
5. 学业要求、学业质量、教学提示和案例单独登记审计进度，不能把内容要求映射完成表述为整个课标完全覆盖。

验收：157 条全部有审计记录；普通与选学分开统计；每项都有可定位来源或明确待核原因；源文件版本与页码体系不混用；记录审核者、时间、意见，未审核项不显示为已通过。

### P0-2 初中统计与概率样板

基线为现有 43 个节点与 13 条课标内容要求。另将原 os-taxonomy review 中独立编写的 18 个候选能力作为对照意见，不直接覆盖现有数据。

交付建议：`reviews/math-junior/statistics/node-review.json`、`edge-review.json`、`question-review.json`、`REVIEW.md`。

| 首批事项 | 处理方式 |
|---|---|
| 组内离差平方和分类，`cms-2022:4.SP.06` | 核对例85和正文后补能力、边和任务；限定在课程要求范围，不扩为聚类算法教学 |
| 百分位数 | 检查现有描述及题库是否实际覆盖；不足时新增或扩展，不能只凭名称搜索下结论 |
| 四分位数，`cnm_216` | 明确排序、计算约定、解释能力，核对教材口径 |
| 箱线图，`cnm_305` | 分清读取、绘制、比较；解释须端点约定，核对教材及课标范围 |
| 方差、极差、标准差，`cnm_215` | 审核是否将不同要求层次混为一个节点，决定拆分或范围标记 |
| 概率题型节点 | 区分基础概念、计算方法和题型变体，避免因题型不同而机械增点 |
| 同名或近义能力 | 根据评估证据决定保留、合并或拆分；发生 ID 变化必须保留迁移映射 |

每个节点审核卡包含：旧 ID、修改动作、能力边界、课标子要求、可观察证据、任务和参考答案、典型误区、hard/soft 边理由、待核事项、审核状态。

验收：43 个现有节点和13条要求全部有明确处理结论；每项核心能力至少配两道不同情境或表示方式的审核题，不能只换数字；涉及数值结果独立计算，开放题有评分判据。题量要求仅是 review 起点，不等于掌握测量已充分。

第一轮用户 review 建议集中于：分组分类、四分位数、箱线图、百分位数，以及抽样与概率各一个代表节点。通过样板规则后，再批量修改43个节点。

## P1：修正诊断证据与推断规则

涉及 `diagnose/engine.js`、`diagnose/app.js`、导出数据与 `tests/test_engine.js`。

已确认当前规则：首次答对后，将该点判为掌握并推断所有祖先掌握；两次失败后回溯。祖先遍历包含 hard 和 soft 边。第一阶段优先处理这种证据扩张，而非先换成复杂模型。

建议实现：

1. 分离观测与推断：保存题目 ID、作答结果、是否自评、时间，以及推断原因和引擎版本。直接作答记录不能被推断覆盖。
2. 单题正确展示为“本题通过／初步证据”，不自动等同于稳定掌握。祖先可标为“暂缓测查／推断待确认”，不能伪装成已测。
3. soft 边仅用于推荐与解释，不传播掌握或薄弱状态。hard 边也不是逻辑蕴含，向祖先推断须保留不确定性并允许抽查。
4. 复测优先覆盖不同子能力和不同题面；已看答案后的立即复测单列，避免把刚获得的提示当成独立证据。
5. 预算耗尽、未复测和用户跳过分别记录；“不稳定”“未完成”不能统一当作不会。
6. 学习路径说明“建议先复习的薄弱环节”；未经实证验证不将结果称为确定的学习根因。
7. 旧 localStorage 会话保留版本信息；无法无损迁移时允许导出并重新开始，不能静默将旧掌握结论当新证据。

验收测试：答对高级节点不把 soft 祖先判为掌握；答题猜中不自动清空整条路径；冲突证据保留；撤销和改判可重放；题量上限不会制造已测结果；旧会话处理明确；原有85项测试逐项判断保留或更新，不能为通过旧断言保留错误语义。

教学验证另做：教师独立判断与系统结果对照，记录误判掌握、误判薄弱和答题负担。在有真实评估前，不宣称诊断准确率或测量模型已校准。

## P1：题库质量与先修边审核

### 题库

从统计样板开始，建立“题目—能力证据—课标要求”的映射。核对题干条件、唯一答案、单位、算法约定、解析、干扰项对应误区及重复模板。数值题独立求解；解释、建模和统计活动补充评分量规，避免只用选择题或数值题替代过程性能力。

上游自动核验是有效基础，但同一表达式生成答案与 verify 不能算两份独立证据。人工/独立计算/同源自动核验分别记录，不合成一个笼统的 verified 标记。

验收：样板题库无已知答案错误、无未说明的多解或算法歧义；每项能力有相应任务；开放题不强行自动判分；题目待核状态可被页面识别。

### 先修边

每条边记录能力级理由、反例检验、审核状态。判 hard 时问：是否存在合理任务能在未掌握该先修时完成目标能力？若存在，考虑降为 soft、删除，或拆分目标节点。教材先后顺序不能直接作为 hard 依据。

验收：样板所有边完成逐条审核；无悬空引用、重复边和依赖环；跨小学与初中的边可定位具体能力；对争议边保留待核标记，不伪造教师共识。

## P2：扩展到初中全科及小学衔接

按“统计样板通过 → 数与代数 → 图形与几何 → 综合与实践 → 小学衔接”的顺序扩展。

重点包括：15条无引用要求的性质分类；几何作图与证明的不同能力；根与系数关系节点 `cnm_226` 的“拓展”命名与掌握深度；两项无映射的题型节点明确属于拓展，不为了消除警告而强挂课标；综合实践评价包含过程和报告。

把课标层与教材层分开：前者定义能力要求，后者配置人教版等教材的册次和章节。现有 `grade/semester/chapter` 保留兼容，另用教材映射记录版本、来源、核实状态。高中现有 grade 10–14 的册次编码不得直接当作学生年级。

验收：初中315个基线节点全部有处理记录；新增和拆分节点有迁移说明；所有普通要求都有明确/部分/缺失/待核结论；小学先修边所引用的节点完成同等级别审核。未完成项公开列出，不追求通过强关联制造100%覆盖。

## P2：数据工程与可追溯发布

采用渐进兼容方案：优先用独立 JSON 保存来源、审核、教材映射和证据，暂不重写全部 topic 字段。新增结构配 JSON Schema 和验证器。

发布时记录数据版本、引擎版本、源版本、基线提交、校验摘要及迁移表。生成器必须同步更新，重建结果应一致。CI执行引用完整性、要求层次与选学标记、ID稳定性、图结构、题目映射、引擎回归与关键浏览器流程检查。

页面显示对应内容的审核状态及来源，区分待核内容、已审核内容、实际作答证据与推断。数据导出包含版本和来源，便于复现。

验收：重复构建一致；历史 ID 可解析；来源链接和定位字段有效；更新不会丢用户记录；PC和窄屏完成选点、作答、改判、结果和导出流程。
